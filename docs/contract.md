# API келісімі — v1.3

Нұрболат бекіткен сервер мен интерфейс арасындағы келісім.
Жобаның барлық бөлігін, соның ішінде сервер мен интерфейсті, Нұрболат жалғыз әзірлейді.
Base URL: `http://127.0.0.1:3001/api`. JSON UTF-8, сұрау өлшемі ≤128 KiB.
POST/PATCH үшін `Content-Type: application/json` қажет.

## Карточка

`Task`: `id`, `description`, `fields`, `status` (`draft|published`), `version`,
`createdAt`, `updatedAt`, `reviewedAt` (ISO уақыт немесе null), `rating`,
`ownership` (`account|token`), `canManage` (ағымдағы сұраудың рұқсаты).

Барлық сегіз өріс әрдайым бар. Әрқайсысы `{ "value": "мәтін", "confirmed": false }`.

| Өріс | Мазмұны | Ұпай |
| --- | --- | ---: |
| title | Атау, 200 таңбаға дейін | 0 |
| context | Мәселе және бизнес қажеттілігі | 20 |
| users | Пайдаланушылар | 10 |
| data | Деректер мен материалдар | 20 |
| expectedResult | Күтілетін нәтиже | 15 |
| successCriteria | Жетістік критерийлері | 15 |
| constraints | Мерзім, технология, қолжетімділік және өзге талаптар | 10 |
| contact | Байланысу тәсілі және кері байланыс форматы | 10 |

Басқа мәтіндік өрістер 10000 таңбаға дейін. Бос мән: `""`; бос өрісті растауға болмайды.
`rating`: `{score, level, breakdown: [{field, max, points}]}`. Ұпайды тек сервер есептейді.
Рейтинг — тапсырманың толықтығы, компания беделі емес.

## Иесінің рұқсаты

Аккаунтқа кірген пайдаланушының жаңа тапсырмасы сол аккаунтқа байланады;
`ownerToken` қайтарылмайды. Иесінің рұқсаты HttpOnly сессия cookie-і арқылы тексеріледі.
Қонақтың draft жауабындағы `ownerToken` тек бір рет беріледі. Оны иесінің сессиясында сақтаңыз;
URL-ге, логқа немесе жария карточкаға қоспаңыз. Жеке әрекеттерге
`Authorization: Bearer <ownerToken>` жіберіледі. OpenAI кілті бұл токеннен бөлек,
ол тек серверде болады. Қонақ токенін және ұмытылған құпиясөзді қалпына келтіру әзірге жоқ.

## Маршруттар

| Әдіс және жол | JSON body | Жауап | Иесі қажет |
| --- | --- | --- | --- |
| POST /tasks/draft | `{description}` | 201 `{task, ownerToken}` | Жоқ |
| POST /tasks/:id/clarify | `{language?: "kk" немесе "ru"}` | 200 `{taskVersion, source, questions, reason?}` | Иә |
| POST /tasks/:id/translate | `{language: "kk" немесе "ru"}` | 200 `{taskVersion, source, language, fields, reason?}` | Жоба үшін иә |
| PATCH /tasks/:id | `{version, fields}` | 200 `{task}` | Иә |
| POST /tasks/:id/publish | `{version, reviewed: true}` | 200 `{task}` | Иә |
| GET /tasks | — | 200 `{tasks: [...]}` | Жоқ |
| GET /tasks/mine | — | 200 `{tasks: [...]}` | Аккаунт қажет |
| POST /tasks/:id/claim | `{}` | 200 `{task}` | Аккаунт және ескі иелік токен |
| GET /tasks/:id | — | 200 `{task}` | Жоба үшін иә |
| POST /tasks/:id/proposals | `{teamName, contact, message}` | 201 `{proposal}` | Жоқ |
| GET /tasks/:id/proposals | — | 200 `{proposals: [...]}` | Иә |
| PATCH /proposals/:id | `{version, status: "accepted" немесе "rejected"}` | 200 `{proposal}` | Тапсырма иесі |
| GET /health | — | 200 `{ok: true}` | Жоқ |

`clarify` кемінде үш сұрақ қайтарады: `{field, question}`.
`language` көрсетілмесе `kk` қолданылады; резервтік сұрақтар да таңдалған тілде келеді.
`source`: `openai|fallback`; fallback себебі: `not_configured|api_unavailable|invalid_response`.
Сұрақтар карточканы өзгертпейді. Жауаптарды тиісті өрістерге PATCH арқылы сақтаңыз:

```json
{
  "version": 1,
  "fields": {
    "title": { "value": "Қойма есебі", "confirmed": true },
    "context": { "confirmed": true },
    "data": { "value": "Тауарлардың CSV тізімі", "confirmed": false }
  }
}
```

Өрістің тек `value` не `confirmed` бөлігін өзгертуге болады. Мән өзгерсе,
`confirmed` көрсетілмеген жағдайда false болады. Әр PATCH карточканы draft күйіне
қайтарады, жалпы шолуды жояды және version арттырады. Өзгермеген өрістер сақталады.
Адам жаңа мәнді сол PATCH-та оқып растаған болса, `confirmed: true` жібере алады.

Жариялау: атау және **барлық толтырылған өрістер** расталған болуы керек;
`reviewed: true` тек адам карточканы қарап, батырманы басқаннан кейін жіберіледі.
Бос өрістерді толтыру міндетті емес, рейтинг шегі жоқ. Төмен рейтингті карточка
да каталогта көрінеді және ұсыныстар қабылдайды. Өңдеу кезінде жариялаудан алынса,
бұрынғы ұсыныстар сақталады, жаңасы қайта жариялағаннан кейін қабылданады.

`Proposal`: `id`, `taskId`, `teamName` (1–200 таңба), `contact` (1–1000),
`message` (1–10000), `status` (`pending|accepted|rejected`), `version`,
`createdAt`, `decidedAt` (ISO уақыт немесе null). Шешім тек қолмен жасалады;
оны кейін өзгертуге болады. Бір тапсырма бірнеше ұсынысты қабылдай алады.

`version` міндетті: соңғы жауаптағы мәнді жіберіңіз. Ескірген мәнге 409 келеді;
карточканы/ұсыныстар тізімін қайта жүктеп, өзгерісті адаммен салыстырыңыз.
`taskVersion` сұрақтардың карточканың қай нұсқасына қатысты екенін көрсетеді.

## Қателер және браузер

Қате пішімі: `{ "error": { "message": "..." } }`.
400 — валидация; 401 — кіру қажет/кіру деректері дұрыс емес;
403 — иесі/Origin сәйкес емес; 404 — табылмады;
409 — ескі нұсқа немесе жарияланбаған тапсырма; 413 — үлкен сұрау;
415 — JSON емес; 429 — кіру әрекеттерінің лимиті; 500 — ішкі қате.
Белгісіз JSON қасиеттері қабылданбайды.

CORS сайттың өз origin мәніне және `FRONTEND_ORIGIN` мәніне рұқсат береді (әдепкі `http://localhost:5173`).
Интерфейс портын ауыстырсаңыз, сервер айнымалысын жаңартыңыз.
Пайдаланушы мәтінін HTML ретінде емес, plain text ретінде көрсетіңіз.
Каталог MVP үшін толық тізімді қайтарады; pagination әзірге жоқ.

## Аударма және кіріктірілген сайт

`GET /` сайтты, `/app.js` және `/style.css` оның ресурстарын береді.
`/account.js` кіру/тіркелу интерфейсінің модулін береді.
Сервер файлдары, `.env.local` және SQLite базасы веб арқылы берілмейді.

`translate.fields` — сегіз өрістің `{fieldName: "аударылған мәтін"}` картасы.
`source: "openai"` болса, бұл тек көрсетілімге арналған ИИ аудармасы.
`source: "original"` болса, `reason` — `not_configured|api_unavailable|invalid_response`,
`fields` ішінде түпнұсқа бар. Мұндай жауап аударылды дегенді білдірмейді.
15 секундтық шектеу бар. Сәтті аудармалар task ID, version, language бойынша
100 жазбаға дейін сервер жадында кэштеледі. Бос өрістер бос күйінде сақталады.
Аударма task version, fields.confirmed, status немесе rating мәндерін өзгертпейді.
Өңдеу мен жариялау тек түпнұсқа карточкаға қолданылады.

## Аккаунттар және сессиялар

| Әдіс және жол | JSON body | Жауап |
| --- | --- | --- |
| POST /auth/register | `{name, email, password}` | 201 `{user}` және Set-Cookie |
| POST /auth/login | `{email, password}` | 200 `{user}` және Set-Cookie |
| GET /auth/me | — | 200 `{user}`; сессия жоқ болса `{user: null}` |
| POST /auth/logout | `{}` | 200 `{ok: true}` және cookie өшіру |

`User`: `{id, name, email}`. Email кіші әріпке келтіріледі және бірегей.
Атау 1–100, email 254-ке дейін, құпиясөз 12–128 таңба; тек бос орындардан
тұратын құпиясөз қабылданбайды. Құпиясөз/хэш/сессия токені JSON жауапқа кірмейді.
Құпиясөз хэші: Node scrypt (`N=65536, r=8, p=2`), кездейсоқ 16-byte salt.
Сессия: кездейсоқ 32-byte cookie, базаға оның SHA-256 хэші ғана сақталады.

Cookie: `shoqan_session`, HttpOnly, SameSite=Strict, Path=/, Max-Age=604800.
HTTPS үшін `COOKIE_SECURE=true` қажет. Бір origin ішіндегі `fetch` cookie-ді
автоматты жібереді; бөлек, same-site интерфейсте `credentials: "include"` қажет.
Басқа сайттан жазу сұраулары қабылданбайды. Барлық POST/PATCH JSON болуы керек.
Сәтті қайта кіру сұраудағы ескі сессияны алмастырады. Шығу ағымдағы сессияны жояды.

Аккаунт тапсырмаларында `ownerId` және `ownerHash` клиентке берілмейді.
Қонақ токені аккаунт тапсырмасын ашпайды. `GET /tasks/mine` тек кірген
пайдаланушыға тиесілі тапсырмаларды, соның ішінде draft-тарды қайтарады.
`canManage` әр жауапта ағымдағы cookie/токен бойынша қайта есептеледі.

`claim` қонақ тапсырмасын кірген аккаунтқа байлайды. Бұрынғы токен жарамсыз болады;
мазмұн, version, status, rating, растау және ұсыныстар өзгермейді.
Басқа аккаунт тапсырмасын немесе `demo-*` ортақ тапсырмасын иемденуге болмайды.
Өз аккаунтына қайта claim жасау өзгеріс енгізбейді.

Кіру мен тіркелуге ортақ лимит — нақты socket IP бойынша 15 минутта 15 сұрау;
X-Forwarded-For ескерілмейді. Лимит бір процестің жадында сақталады.
Email растау және құпиясөз қалпына келтіру бұл нұсқада жоқ.

## Сұрау лимиттері

Бір сервер процесінде API үшін минутына 1200 жалпы сұрау, нақты socket IP үшін
240 сұрау, соның ішінде 60 POST/PATCH және 30 translate/clarify сұрауы қабылданады.
Шектен асса 429 және `Retry-After` (секунд) қайтарылады. `/api/health` және
сайттың статикалық файлдары бұл лимиттерге кірмейді.

OpenAI-ға нақты шығыс сұраулар бөлек шектеледі: әдепкі 24 сағаттық терезеде 200,
бір мезетте 3. `AI_REQUESTS_PER_DAY` және `AI_MAX_CONCURRENT` арқылы бапталады.
Кэштен берілген аударма және кілтсіз резервтік жауап шығыс бюджетіне кірмейді.
Бюджет біткенде немесе барлық слот бос емес болса, нақтылаушы сұрақтар резервтен,
аударма түпнұсқадан беріледі; `reason: "rate_limited"` қосылады.
Барлық лимиттер процесс жадында, сервер қайта іске қосылғанда тазарады.
